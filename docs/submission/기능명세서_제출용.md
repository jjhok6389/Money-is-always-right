## 1. MVP 구현 범위*

> 제출한 예선 MVP 산출물에서 구현한 기능 범위 작성
> 미구현 또는 향후 구현 예정 기능은 제외

### ① 서비스 개요

- 서비스명: AI 기반 청년자산 나침반
- 형태: 웹 애플리케이션 (React SPA + FastAPI REST API)
- 대상: 자산 형성 초기 단계의 청년 금융소비자
- 범위: 「재무 진단 → 목표 Gap 분석 → What-if 시뮬레이션 → AI 코칭 → 코칭 리포트」 전 구간을 실제 동작 기능으로 구현

### ② 구현 범위

| 영역 | 구현 범위 |
| --- | --- |
| 인증·온보딩 | Firebase Auth 기반 회원가입·로그인·비밀번호 재설정, 3단계 온보딩(인적사항 · 투자성향/목표 · 마이데이터 연동 시뮬레이션), 설문 기반 투자성향 자동 진단(내 투자성향 알아보기), Firestore 프로필 저장·조회·수정 |
| 소비 데이터 | 마이데이터 표준 참고 가상 거래 생성(사용자 ID·월 시드 기반 재현), 카테고리 분류, 고정·변동 지출 구분, 월별 소비 집계 |
| 금융상품 데이터 | 금융감독원 「금융상품 한눈에」 Open API 기반 정기예금·적금·연금저축 조회 및 최고금리 산출, 키 미보유 시 Mock 경로 사용 |
| 시장 데이터 | KRX ETF 일별 시계열 적재(일배치), 약 126거래일 연율화 변동성 산출, 사분위 위험버킷 분류, 성향별 ETF 추천 및 상세·시계열 조회 |
| 개인화 대시보드 | 자산 포트폴리오 시각화, 소비 분석, 목표 Gap·달성률·달성 예상 시점, 월 저축 여력, 규칙 기반 로드맵, 상품·ETF 큐레이션, 부채 상환 우선순위 |
| 디지털 트윈 | 프로필 기반 기준 계획(Baseline) 생성, 소득·지출·저축률·수익률 변경 시나리오 계산, 궤적 비교 차트 |
| AI 금융 코치 | AWS Bedrock Converse 기반 Tool-calling Agent, 8종 도구 연계, RAG 지식 검색, 실행 트레이스 노출, 플로팅 챗봇 UI |
| 코칭 리포트 | 장면형(스토리형) 코칭 리포트 생성·저장·재생, 직전 리포트 대비 비교, 월간 리포트 수신일 설정 |
| 금융 튜토리얼 | 급여·현금흐름·저축·투자·ETF·금융사기 예방 6챕터 학습, 실습형 인터랙션, 퀴즈, 진행도 저장, 구간(3챕터)·완주(6챕터) 보상 지급 |

### ③ 본 명세서 제외 범위

- 마이데이터·오픈뱅킹 실계좌 연동 (MVP는 Mock 거래 데이터 사용)
- 페르소나 프리셋 및 CSV 거래 업로드
- 리포트 푸시·이메일 알림 발송
- 시나리오 영속화 및 다중 시나리오 비교
- 모바일 앱(네이티브) 및 PWA

### ① 인증 및 온보딩

| 기능명 | 기능 설명 | 관련 화면 |
| --- | --- | --- |
| 회원가입 | 이메일·비밀번호 기반 계정 생성 후 온보딩으로 자동 이동 | `/signup` |
| 로그인 | Firebase Auth 인증 및 ID Token 발급, 온보딩 완료 여부에 따른 라우팅 분기 | `/login` |
| 비밀번호 재설정 | 등록 이메일로 재설정 메일 발송 | `/forgot-password` |
| 접근 제어 | 미인증 사용자 로그인 화면 이동, 온보딩 미완료 사용자 온보딩 강제 | 전 화면 |
| 온보딩 입력 | 3단계 입력(이름·나이·직업 / 투자성향·목표금액·목표기간·목표설명 / 마이데이터 연동 시뮬레이션) | `/onboarding` |
| 투자성향 선택 | 금융투자협회 표준투자권유준칙 기준 5단계(안정형·안정추구형·위험중립형·적극투자형·공격투자형) 선택 | `/onboarding` |
| 투자성향 진단(설문) | 5단계 투자성향을 직접 선택하지 않고 문항 응답 기반으로 자동 산출(나이·목표기간 보조 반영) | `/onboarding` |
| 금융데이터 연동 시뮬레이션 | 온보딩 3단계에서 마이데이터 연결 과정을 애니메이션으로 체험(실제 기관 로그인 없음), 완료 시 Demo 보유·거래 데이터가 대시보드에 반영 | `/onboarding` |
| 프로필 저장·조회·수정 | 온보딩 결과를 Firestore `users/{uid}`에 저장하고 대시보드·시뮬레이션·코치에 제공, 마이페이지에서 이름·나이·직업·투자성향·목표 재수정(월 소득·고정비는 Demo 거래 기준 조회 전용, 수정 불가) | `/onboarding`, `/mypage` |

> **[그림 1] 온보딩 — 투자성향 진단 및 마이데이터 연동 시뮬레이션**
> - **형태**: 실제 구현 화면 캡처 (`/onboarding`)
> - **내용**: 2단계의 「내 투자성향 알아보기」 진단 버튼·결과 화면과 3단계 마이데이터 연동 시뮬레이션(연결 진행 애니메이션) 화면
> - **출처**: 캡처 조건 — 신규 회원가입 직후 온보딩 진행 중
> - **의도**: 3단계 온보딩과 설문 기반 투자성향 자동 진단이 실제 동작함을 입증

### ② 데이터 관리

| 기능명 | 기능 설명 | 관련 화면 |
| --- | --- | --- |
| 가상 거래 생성 | 사용자 ID와 기준월(`YYYY-MM`) 시드로 재현 가능한 마이데이터 형식 거래 내역 생성 | `/transactions` |
| 거래 분류·가공 | 가맹점·적요 기준 소비 카테고리 분류 및 고정·변동 지출 구분, 카테고리별 집계 | `/transactions` |
| 거래 조회·필터 | 기준월 변경, 재생성, 전체·소득·고정·변동·저축 5종 필터로 거래 내역 확인 | `/transactions` |
| 예·적금·연금저축 조회 | 금융감독원 Open API로 상품 목록·기간별 금리 조회, 최고금리 및 최적 기간 산출 | `/products` |
| 상품 데이터 대체 경로 | API 키 미설정 시 동일 스키마 Mock 데이터 반환 및 `source` 필드로 출처 표기 | `/products`, `/dashboard` |
| ETF 원장 일배치 | KRX ETF 일별매매정보를 정해진 시각(KST)에 수집하여 저장소·지식베이스로 동기화 | 백엔드 배치 |
| ETF 변동성 산출 | 약 126거래일 종가 기준 연율화 변동성 계산 및 사분위 위험버킷 분류 | `/dashboard` |

> - **의도**: 가상 거래 가공과 금감원 공시 상품 데이터 연동이 실제 동작함을 입증

## 3. 사용자 이용 흐름*

> 사용자가 배포 URL 접속 후 주요 기능을 사용하는 순서 작성

### ① 최초 이용 흐름

1. 배포 URL 접속 → 미인증 상태이므로 로그인 화면(`/login`) 표시
2. 「회원가입」 선택 → 이메일·비밀번호 입력으로 계정 생성
3. 온보딩 1단계 → 이름·나이·직업 입력
4. 온보딩 2단계 → 투자성향 5단계 중 선택(또는 「내 투자성향 알아보기」 진단 도구로 문항 응답 기반 자동 판정), 목표 금액·목표 기간·목표 설명 입력
5. 온보딩 3단계 → 마이데이터 연동 시뮬레이션 진행(Demo 데이터로 대시보드 채움) 후 저장
6. 온보딩 저장 완료 → 자동으로 `/coach-report?onboarding=1` 인트로 화면("회원가입이 완료되었습니다!") 표시 → 「나의 첫 금융 리포트 보기」 클릭 → 장면형 리포트 재생
7. 첫 리포트 확인 후 홈(`/`) 진입 → 재무 대시보드 및 주요 기능 진입점(상단 내비게이션) 확인

### ② 핵심 기능 이용 흐름

1. **소비 확인** — `/transactions`에서 기준월 거래 내역과 카테고리별 고정·변동 지출 구조 확인
2. **재무 진단** — `/dashboard`에서 포트폴리오, 소비 분석, 목표 Gap·달성률·달성 예상 시점, 월 저축 여력, 로드맵, 추천 상품·ETF 확인
3. **상품 탐색** — `/products`에서 예금·적금·연금저축 목록 및 최고금리 조건 확인
4. **시뮬레이션** — `/simulation`에서 지출·저축률 등 변수를 조정하고 기준 계획 대비 자산 궤적·달성 시점 변화 비교
5. **AI 코칭** — 우하단 챗봇 호출 후 질문 입력, 답변과 함께 사용된 도구 실행 트레이스 확인
6. **코칭 리포트** — `/coach-report`에서 리포트 생성 → 장면형 플레이어로 진단·개선 지점·시뮬레이션 결과 순차 확인
7. **재열람·후속 관리** — `/reports`에서 리포트 목록 재열람, 월간 비교 리포트 생성, 월간 리포트 수신일 설정
8. **프로필 갱신** — `/mypage`에서 목표·투자성향 수정 후 대시보드 재계산
9. **금융 학습** — `/tutorial`에서 챕터별 개념·실습·퀴즈 진행, 구간(3챕터)·완주(6챕터) 보상 확인

## 4. AI 및 데이터 처리 방식*

> AI가 수행하는 역할 작성
> 사용 데이터와 입력·출력 데이터 작성
> (필요시) 개인정보 또는 민감정보 처리 여부 작성

### ① AI가 수행하는 역할

- 사용 모델: AWS Bedrock Converse API 기반 Amazon Nova Lite 사용, 임베딩은 Amazon Titan Embed Text V2 사용
- 구조: 도구 사용(Tool-calling) Agent — 사용자 질문 의도를 해석하여 필요한 도구를 스스로 선택·호출하고 결과를 종합해 한국어로 응답
- 역할 분리 원칙
  - 수치: AI가 생성하지 않고 데이터 조회·계산 도구 결과만 인용 (자산·Gap·저축 여력·시뮬레이션 결과)
  - 설명: 금융용어·정책금융·상품 우대조건·ETF 개념은 RAG 검색 문서를 근거로 설명
  - 로드맵: 서비스의 규칙 기반 분석 결과를 조회하여 설명하는 역할만 수행
- 신뢰성 확보: 사용 도구·상태·요약을 실행 트레이스로 노출, 지식 문서의 출처·검증 정보 관리, 평가 세트로 검색·답변 품질 점검
- 안전장치: 투자 권유가 아니며 과거 변동성이 미래 수익을 보장하지 않는다는 고지를 프롬프트 및 응답 단계에서 강제, 수익률 예측·단정적 투자 판단 표현 금지
- 장애 대응: Bedrock 호출 실패 또는 키 미설정 시 동일 도구를 사용하는 로컬 응답 경로로 전환하고 응답 출처(`source`)를 표기

### ② 사용 데이터

| 데이터 | 출처 | 활용 |

### ④ 개인정보 및 민감정보 처리

- 수집 항목: 이메일, 비밀번호(Firebase Auth 관리, 서비스 서버 미저장), 이름·나이·직업, 투자성향, 목표 금액·기간·설명
- 미수집 항목: 주민등록번호, 계좌번호, 카드번호 등 실금융 식별정보 — MVP는 실계좌·마이데이터에 접속하지 않으며 거래 데이터는 전부 가상 생성 데이터 사용
- 저장·접근: 프로필은 Firestore `users/{uid}`에 저장하고 본인 문서만 접근 가능하도록 보안 규칙 적용, 모든 API는 Firebase ID Token(Bearer) 검증 후 처리
- 외부 전송: AI 응답 생성을 위해 재무 요약 값과 이름·나이·직업·투자성향·목표 등 프로필 요약이 Bedrock으로 전달되며, 계좌번호 등 실금융 식별정보는 전송하지 않음
- 자격 증명 관리: 외부 API 키·서비스 계정 키는 서버 환경변수로만 관리하고 저장소에 포함하지 않으며, 민감하지 않은 설정값만 프론트엔드에 노출

### ④ 실행 환경 및 브라우저 제한사항

- 권장 브라우저: Chrome, Edge 등 최신 Chromium 계열 (Safari·Firefox 최신 버전 동작 확인)
- Internet Explorer 미지원
- 데스크톱 화면 기준으로 UI를 구성하였으며 모바일 브라우저에서는 차트·챗봇 레이아웃이 최적화되지 않음
- 회원가입 및 API 호출에 네트워크 연결 필요, 브라우저 쿠키·로컬 저장소 차단 시 로그인 상태 유지 불가
- 최초 호출 시 외부 Open API 및 AI 응답 대기로 수 초의 지연이 발생할 수 있음

### ⑤ MVP 단계 제한사항

- 소비 거래는 마이데이터 표준을 참고한 가상 데이터이며 실계좌·오픈뱅킹과 연동되지 않음
- 예·적금 및 ETF 데이터는 API 키 보유 여부에 따라 실데이터 또는 Mock으로 동작하며, 응답의 `source` 필드로 출처를 구분함
- 지식 코퍼스는 MVP 범위의 표본 문서로 구성되어 있어 정책금융 공고 원문 등 전량 반영은 향후 확대 예정
- 시뮬레이션은 월복리 단순 투사 모델로 세금·물가·중도 해지 등 변수는 미반영
- 시나리오는 조회 시점에만 계산되며 저장·다중 비교 기능은 미구현
- 코칭 리포트 수신일 설정은 일정 저장까지만 지원하며 푸시·이메일 발송은 미구현
- 본 서비스의 분석·추천 결과는 정보 제공 목적이며 투자 권유가 아님
