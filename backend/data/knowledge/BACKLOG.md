# 지식 코퍼스 백로그

`scripts/eval_knowledge.py` 측정 결과를 근거로 정리한 **추가로 필요한 문서 목록**.
선정 기준은 *지금 사용자가 물어볼 수 있는데 답할 문서가 없는가* 이며,
근거는 `coach_service.ROUTING_RULES` 의 라우팅 키워드, `SUGGESTIONS` 추천 질문,
그리고 `dashboard_service`·`simulation_service` 가 다루는 도메인이다.

## 측정이 말해주는 것 (2026-08-24 기준, 코퍼스 112건 / 평가 32건)

합집합 검색 도입 후 **`recall@set` 은 모든 그룹에서 1.000** 이다 —
검색기는 정답을 놓치지 않는다. 남은 문제는 **없는 문서를 못 만드는 것**뿐이다.

| 그룹 | recall@set | low_label_rate | 해석 |
|---|---|---|---|
| `glossary` | 1.000 | — | 용어는 해결됨. 확충보다 유지가 우선 |
| `product` | 1.000 | — | 상품명을 말한 질문은 완벽. **상품 문서 추가 불필요** |
| `policy` | 1.000 | — | 문서는 찾아지지만 **내용이 자리표시자라 답변 불가** |
| `gap` | — | 0.750 | 문서가 없는 주제. 4건 중 1건은 low 로도 못 걸러냄 |

**핵심: 검색기가 아니라 코퍼스가 병목이다.**

특히 `eval-031` "청년내일저축계좌"(짧은 질의)는 **청년도약계좌 자리표시자를 벡터 0.3796** 으로
가져오는데, 이는 정답 케이스 다수보다 높은 점수다. **임계값으로는 절대 못 막는다.**
지금은 모델이 문서의 `[미검증 자리표시자]` 표기를 읽고 거절하는 것으로 막고 있다 —
동작하지만 문서를 채우는 것이 근본 해결이다.

## 문서 추가 절차

1. `glossary.jsonl` / `policy.jsonl` 에 줄 추가 (스키마: `README.md`)
2. `python -m scripts.build_knowledge_index` 로 재빌드
3. `python -m scripts.eval_knowledge --baseline runs/base.json` 로 **회귀 확인**
4. 새 문서에 대응하는 평가 케이스를 `data/eval/knowledge_eval.jsonl` 에 추가하고,
   해당 `gap` 케이스는 `expected` 를 새 문서 id 로 바꿔 그룹을 옮길 것

> P0 문서를 채울 때 **자격요건·금액을 추측해서 쓰지 말 것.** 공고 원문을 확인하고,
> 확인 못 한 항목은 문서에서 빼거나 `source` 에 미확인임을 남긴다.
> 시스템 프롬프트가 "미검증 표시 문서는 확정 사실처럼 말하지 않는다"를 지키도록 되어 있다.
